# 2. OBJETIVO PRINCIPAL

O sistema deve permitir que o consultor:

1. cadastre uma autoescola;

2. inicie uma reunião;

3. faça perguntas estruturadas aos donos e à equipe;

4. registre respostas rapidamente;

5. calcule métricas automaticamente;

6. identifique gargalos;

7. identifique oportunidades comerciais;

8. atribua prioridade às oportunidades;

9. estime impacto financeiro;

10. gere um diagnóstico visual;

11. monte automaticamente um plano de 90 dias;

12. gere uma proposta comercial personalizada;

13. apresente o valor recomendado;

14. registre o resultado da reunião;

15. salve todo o histórico.

O sistema deve funcionar como um **copiloto de vendas consultivas**.

---

# 3. PRINCÍPIO FUNDAMENTAL

Nunca trate uma resposta isoladamente.

Cada resposta deve alimentar uma ou mais variáveis do diagnóstico.

Exemplo:

Pergunta:

"Quanto tempo leva para um novo lead receber a primeira resposta?"

Resposta:

"30 minutos."

O sistema deve automaticamente:

* classificar velocidade como ruim;

* aumentar score de gargalo de atendimento;

* disparar oportunidade "Atendimento Imediato";

* calcular potencial de recuperação;

* adicionar essa oportunidade ao diagnóstico;

* considerar essa informação na recomendação final.

O consultor não deve precisar fazer cálculos manualmente.

# 54. CRITÉRIO DE QUALIDADE

Não entregue apenas uma interface bonita.

O produto precisa parecer e funcionar como um software comercial real.

Evite:

* lorem ipsum;

* botões sem função;

* telas estáticas;

* números hardcoded;

* gráficos falsos;

* formulários sem persistência;

* navegação quebrada;

* componentes genéricos;

* excesso de cards;

* telas vazias;

* cálculos manuais.

Toda métrica deve ser derivada dos dados.

Toda oportunidade deve ter uma regra.

Toda recomendação deve ter justificativa.

# 55. ENTREGÁVEL

Construa o sistema completo, funcional e navegável.

Prioridade:

1. funcionalidade;

2. lógica;

3. experiência do consultor;

4. cálculos;

5. persistência;

6. inteligência;

7. design premium.

Não simplifique o projeto para uma landing page.

Não transforme o produto em um formulário.

Não remova módulos importantes para "facilitar".

Se alguma integração externa não puder ser implementada imediatamente, crie uma camada de serviço bem abstraída e um mock funcional, mantendo a arquitetura pronta para conexão futura.

O resultado deve parecer um produto SaaS que uma consultoria de alto nível realmente utilizaria para diagnosticar e vender projetos para autoescolas.

# REGRA FINAL

Antes de implementar qualquer tela, pense:

> **"Como um consultor conseguiria usar isso durante uma reunião de 60–90 minutos, conversando com dois donos e uma recepcionista, sem perder o ritmo da conversa?"**

A interface deve permitir que o consultor converse com o cliente e, ao mesmo tempo, registre informações rapidamente.

O sistema deve fazer o trabalho pesado:

**perguntar → calcular → interpretar → detectar → priorizar → projetar → recomendar → apresentar.**

O consultor deve fazer o que um consultor humano faz melhor:

**conversar → investigar → gerar confiança → explicar → negociar → fechar.**
